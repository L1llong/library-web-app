## 1. Название и организация
- Название системы: АИС «БиблиоКонтроль» (Управление выдачей книг)
- Организация / подразделение: МБУК «Централизованная библиотечная система» г. Казани (филиал № 12)
- № из таблицы примеров: 94

## 2. Главная сущность и справочник
- Главный объект (одна запись процесса): Заявка на выдачу книги (BookRequest)
- Справочник (вторая таблица, ссылка числом): Книга (Book)
- Поле-ссылка (как назовёте в JSON/БД): `bookId`

## 3. Роли и права

| Роль | Создаёт | Назначает | Меняет статус |
| --- | --- | --- | --- |
| Читатель | да | нет | нет |
| Библиотекарь | да | нет | да |
| Заведующий филиалом | нет | да | да |

*Исполнитель (библиотекарь) не назначает себя, назначение делает заведующий или система.*

## 4. Сценарий в одно предложение
Читатель создаёт заявку на книгу -> заведующий (или система) назначает ответственного библиотекаря -> библиотекарь меняет статус заявки на "Выдана" или "Отменена".

## 6. Что не входит в семестр
1. Интеграция с федеральными библиотечными системами (РНБ, РГБ).
2. Мобильное приложение для читателей.
3. Система онлайн-оплаты штрафов за просрочку.
4. Сканирование штрих-кодов/RFID через веб-камеру или терминал.

## 7. Запас под ВКР
1. **Данные/процесс**: Автоматический расчет и начисление штрафов за просроченные книги с формированием реестра должников для печати.
2. **Связь с другими системами**: Интеграция с системой «Электронный читательский билет» (Госуслуги) для автоматической верификации данных пользователя.
3. **Масштаб**: Разработка подсистемы аналитики и сводных отчетов для всей сети библиотек (ЦБС г. Казани), а не только одного филиала.
4. **Данные/процесс**: Внедрение алгоритма рекомендательной системы для читателей на основе истории их выдач (коллаборативная фильтрация).

## 8. Чем не копия соседа
Другая предметная область (библиотека, а не ремонт/вуз/склад), главный объект - заявка на выдачу книги, справочник - книги, роли: читатель, библиотекарь, заведующий. Конкретная организация: МБУК «ЦБС» г. Казани.
