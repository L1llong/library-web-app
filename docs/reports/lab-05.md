## 1. Цель работы

Связать поля формы создания заявки с общим массивом через `v-model`,
добавить клиентскую валидацию по правилам ЛР1 и убедиться, что без сервера
данные живут только в памяти вкладки браузера.

---

## 2. Таблица "script / template"

| Скрипт (`<script setup>`) | Шаблон (`<template>`) |
| --- | --- |
| `const form = ref({ title: '', bookId: 0, description: '' })` | `v-model="form.title"` |
| `errors = ref({ title: '', bookId: '', description: '' })` | `v-if="errors.title"` + `{{ errors.title }}` |
| `validate()` проверяет длины и число | `v-model.number="form.bookId"` |
| `addItem(...)` из `requestStore.js` | `@submit.prevent="onCreate"` |
| `router.push('/')` после успеха | `<button type="submit">Создать заявку</button>` |

---

## 3. Правила валидации (из ЛР1)

| Поле | Правило | Текст ошибки |
| --- | --- | --- |
| `title` | 5–80 символов после `trim` | "Тема: от 5 до 80 символов" |
| `bookId` | целое число больше нуля | "ID книги: целое число больше нуля" |
| `description` | 10–500 символов | "Описание: от 10 до 500 символов" |

Если хотя бы одно правило нарушено - `onCreate` делает `return` до вызова
`addItem`, запись в массив не попадает.

---

## 4. Три доказательства

| Проверка | Что делал | Факт |
| --- | --- | --- |
| Успех | тема "Гарри Поттер", `bookId = 7`, описание ≥ 10 | строка `REQ-2026-003` со статусом `New` появилась в списке |
| Отказ | тема `abc`, описание `коротк` | ошибки видны под полями, строка в таблицу не добавлена |
| Память | F5 после успешного создания | добавленные строки исчезли, остались две тестовые из заготовки |

**По F5:** ожидаемо - сервера и базы данных пока нет, массив живёт только в
оперативной памяти вкладки. При обновлении модуль `requestStore.js`
инициализируется заново. Постоянное хранилище появится в ЛР6 (API) и ЛР10 (БД).
